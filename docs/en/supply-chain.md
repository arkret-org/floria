# Local Supply-Chain Artifacts

This runbook covers local-only release-readiness artifacts for floria. It does
not push container images, create Git tags, publish crates, or attach
attestations to a registry.

## CI image scan

`.github/workflows/docker-images.yml` builds the Docker image into the GitHub
Actions runner, scans that local image with Trivy, and fails the job on
`HIGH` or `CRITICAL` vulnerabilities before any registry push step can run. The
workflow also runs on pull requests; those runs build and scan only.

The Trivy policy is intentionally simple:

```sh
trivy image --severity HIGH,CRITICAL --exit-code 1 --scanners vuln floria:<local>
```

## Local artifact script

Run this from the repository root after installing Docker, Trivy, Syft, and
Cosign:

```powershell
.\scripts\local-supply-chain.ps1 -Image floria:local-supply-chain -CosignKey .\cosign.key
```

The script writes artifacts under `target/supply-chain/` by default:

| Artifact | Description |
|----------|-------------|
| `floria-image.spdx.json` | SPDX JSON SBOM generated by Syft from the local Docker image |
| `floria-slsa-provenance.in-toto.json` | Local in-toto statement with a SLSA provenance v1 predicate |
| `floria-slsa-provenance.sigstore.json` | Optional Cosign bundle for the provenance file when a local key is provided |

To generate a local Cosign key:

```powershell
cosign generate-key-pair
```

Then either pass `-CosignKey .\cosign.key` or set `COSIGN_KEY` before running
the script. The script uses `cosign sign-blob` with `--tlog-upload=false` so the
signature bundle stays local.

## Manual commands

The script is equivalent to this local sequence:

```powershell
docker build --file Dockerfile --tag floria:local-supply-chain .
trivy image --severity HIGH,CRITICAL --exit-code 1 --scanners vuln floria:local-supply-chain
syft docker:floria:local-supply-chain -o spdx-json=target/supply-chain/floria-image.spdx.json
cosign sign-blob --yes --key .\cosign.key --tlog-upload=false --bundle target/supply-chain/floria-slsa-provenance.sigstore.json target/supply-chain/floria-slsa-provenance.in-toto.json
```

Do not use `cosign attest`, `docker push`, `oras attach`, or Git tags for this
local readiness slice. Registry attachment and publication are separate release
steps and are intentionally out of scope here.
